# 需求：點開影片快速開播、不再卡在載入中（fast-start）

日期：2026-11-08

## 目標

點開影片後盡快開始播放（接近官方 App 的即點即播），並消除永遠卡在「載入中」的情況。

## 背景（調查結果）

- 1～3 秒延遲：BTR 代理要等 128 KB 開頭片段完整下載後才送出任何資料（`lib/services/download/btr_proxy.dart:455-477`），影片、音訊、起始位置跳轉各要等一次；送出前還要依序試連最多 3 個節點（`btr_proxy.dart:149-156`、`:205-236`）；playurl 可能被 `_supplementVideoQualities` 再打一次（`lib/pages/video/controller.dart:906-913`、`:960`）；預設畫質為最高（8K／HDR）。
- 卡在載入中：開檔失敗的自動重試只認 `https://`（`lib/plugin/pl_player/controller.dart:1282-1286`），BTR 給播放器的是 `http://127.0.0.1`；mpv `network-timeout=5` 比 BTR 的恢復時間短；改用原始網址也失敗時 `res` 沒有關閉（`btr_proxy.dart:480-483`）。
- 壞節點的失敗紀錄只存在單一網址的 `BtrNodePool`（`btr_proxy.dart:128`），每部影片重學一次。

## 使用者決定（2026-11-08）

修卡住、BTR 快速開播、少一次 API、首次播放畫質上限 1080P。

## 驗收條件

- **AC-1**：BTR 代理在試連取得檔案大小後立即送出 HTTP 回應標頭；開頭片段改為邊下載邊寫給播放器，不等整塊完成。
- **AC-2**：開頭片段約 2 秒內沒有收到任何資料時，改從其他節點或原始網址繼續，不讓播放器空等。
- **AC-3**：試連節點改為同時進行，取第一個成功者；全部失敗時直接使用原始網址直通。
- **AC-4**：節點失敗／封鎖紀錄與速度統計在整個 App 程序內共用（以 host 為單位），新影片不必重新試已知壞掉的節點；封鎖有時效（例如 10 分鐘）。
- **AC-5**：BTR 任何失敗路徑都會關閉回應（不留下未關閉的連線）。
- **AC-6**：播放器開檔失敗（包含 `http://127.0.0.1` 的 BTR 網址）時會自動重試；重試時這部影片改用不經 BTR 的原始網址。
- **AC-7**：mpv `network-timeout` 調整為與 BTR 恢復時間相容的值（不小於 15 秒）。
- **AC-8**：`_supplementVideoQualities` 不再阻擋開播：先用第一次 playurl 結果開始播放，補齊畫質清單在背景完成後更新畫質選單。
- **AC-9**：點卡片時預先取得的 playurl（tap-down prefetch）若與影片頁需要的請求相同（同 bvid／cid、同參數），影片頁直接使用快取結果，不再重打 playurl；預覽仍能從同一結果取得低畫質串流。
- **AC-10**：未手動設定過預設畫質的使用者，Wi-Fi 與行動網路的預設畫質上限都是 1080P；使用者已手動設定的值不變；仍可在播放器手動切換更高畫質。
- **AC-11**：關閉 BTR 時的播放行為不受影響（只有 AC-6、AC-7、AC-8、AC-9、AC-10 適用）。
- **AC-12**：`flutter analyze` 無新增錯誤或警告；release 建置成功。

## 不做的範圍

- 改變 BTR 的節點清單、海外／大陸模式預設值。
- 修改 media_kit 原始碼。
- 番劇／課程的 playurl 預取（只處理一般影片 UGC）。

# 需求：碰到即預覽、開影片計時與快速起播

日期：2026-11-13

## 目標

1. 讓使用者手指一碰到影片卡就看到預覽，不必長按或停住，且不影響上下捲動。
2. 量出開影片到首幀的實際時間，並調整 mpv 起播參數，朝原版 App 的 100~300 ms 靠近（在台灣只能用海外 CDN，不保證達到）。

## 使用者決定（2026-11-13）

- 滑動時：不等待，直接跟著手指所在的卡片預覽。
- 長按：恢復原本的長按動作（不再先觸發預覽）。
- 設定：直接取代現有方式，不新增「碰到即預覽」開關。
- 載入速度：計時與 mpv 起播參數一起做。

## 驗收條件

- AC-1：在有影片卡的列表（首頁推薦、熱門、歷史、稍後再看、收藏、搜尋、直播等使用 `CardPreview` 的卡片），手指按下卡片的瞬間開始預覽該卡，不需長按、不需停住。
- AC-2：按下卡片後上下拖動，列表照常捲動；手指移到另一張卡片時，立刻改預覽那一張（沒有 250 ms 等待）。
- AC-3：輕點卡片仍開啟影片頁，並把預覽進度帶過去（`take()` 行為不變）。
- AC-4：長按卡片直接執行原本的長按動作（選單、稍後再看等），不先觸發預覽；長按時停止這張卡的預覽。
- AC-4a：按下卡片後橫向滑動（切換首頁分頁）時，停止預覽。
- AC-4b：輕點開影片時，帶到影片頁的進度只來自這次預覽；這次預覽還沒有播放位置時不帶進度（不可帶上次同一部影片預覽留下的舊進度）。
- AC-5：設定中「長按影片預覽」總開關仍可整個關閉預覽；「滑動時預覽」開關移除；標題與說明改成碰到即預覽的描述。
- AC-6：每次開影片後，CDN 狀態面板顯示最近一次的開啟耗時：首幀總時間，以及 playurl、開檔（呼叫 `player.open` 到完成）、BTR 首 byte 各段時間；另顯示本次啟動最近 20 次首幀的平均。（原本要求寫入日誌檔；日誌檔為 Catcher JSON 報告格式，寫入自訂行會破壞日誌頁解析，改為面板顯示平均。）
- AC-7：一般影片（非直播、非本機檔）起播時套用快速起播 mpv 參數 `demuxer-lavf-probe-info=nostreams`；設定中有「快速起播」開關（預設開，使用者實機 A/B 後再決定是否保留預設），關掉後恢復原本參數。
- AC-8：`flutter analyze` 沒有新增 issue；release 可建置。

## 不做的範圍

- 不改 PGC（番劇）與直播的開播流程（直播卡片預覽仍適用 AC-1、AC-2）。
- 不改 BTR 多節點下載邏輯本身。
- 不承諾達到 100~300 ms；本次只量測並調參數，後續依實測數字再優化。
- 不做模擬器／實機測試（使用者自己測）。

## 限制

- 介面文字、註解用繁體中文或英文（專案既有英文註解風格可沿用）。
- 用 `C:\src\flutter`（已 patch）建置與 analyze。
- Android 為主要平台。
